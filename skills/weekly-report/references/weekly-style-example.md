# 用户周报风格示例

这是用户过去的真实周报,用作风格基准。写草稿前读一遍校准语气、颗粒度、条目组织方式。

## 风格要点

- 中文,编号列表。每周给的示例有时写成两段(前半偏代码改动,后半偏测试/文档/评估沟通),那只是随手分块,**不是固定结构**——写的时候别硬凑分段,内容自然连贯就行。
- 每条一句话讲清"做了什么 + 为什么/根因",技术细节到模块和机制。
- 同主题小提交合并成一条,不堆碎片。
- 日期用 `月.日`(如 `9.18`),每周一期。

## 从示例里能读出的转译规律

- commit subject 的 `fix(mnt_ns): guard fs_rec NULL deref...` → 周报里写成 "修复 mnt_ns 中 fs_rec 悬空指针崩溃:...",加"根因/做法"。
- `refactor(mnt_ns): replace pty semaphores with sticky events` → "将 PTY 子系统的 semaphore 替换为 sticky event,解决丢失唤醒问题"。
- `feat(shell): add ^\ q escape` → "sessiond 会话列表增加容器名显示,新增 ^\ q 命令在无活跃会话时安全退出"——把多条同主题 feat 合成一条。
- 性能数值(`38ms`、`4.6%`、`7ms本地+13ms板对板`)是用户口头补充的,git 抓不到,必须在确认环节问。
